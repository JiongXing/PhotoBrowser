# Design

## Context

见 proposal.md。CodeGraph 定位了 `Sources/JXPhotoBrowserViewController.swift` 的刷新、导航、轮播与 Cell 创建路径，以及 `Sources/JXZoomImageCell.swift` 的布局、图片加载与缩放回调。PR 使用闭包捕获页码及可见 Cell，当前主线没有尺寸转场契约。

## Goals / Non-Goals

**Goals:** 用一次尺寸转场的明确生命周期协调页码、Cell 和轮播；新刷新或导航即时接管页面状态，沿用现有公开 API。

**Non-Goals:** 不增加通用任务调度/重试系统，不改变宿主方向决策，不保存旋转前放大区域。

## Decisions

- 控制器持有仅存活于尺寸转场期间的上下文，记录最新目标页及参与的 Cell。刷新、有效跳页更新同一目标；动画与完成阶段读取最新目标，不再捕获旧页码。单纯 clamp 不能保护新的有效选中页，故不采用。
- 轮播启动条件统一排除尺寸转场，避免 reloadData 或滚动结束回调提前恢复计时器。转场中止原来的滚动，并最终解除暂停。转场中的显式导航即时选中目标，由系统尺寸动画统一定位，不再叠加独立分页动画；转场外 animated 参数行为保持不变。
- Cell 创建后、交还集合视图前加入当前转场；开始时已有 Cell 和后续 Cell 均有配对准备/结束。复用重置 Cell 本地状态，避免一次旧显示的锁定泄漏。
- 普通布局、缩放回调和图片更新不能覆盖转场正在驱动的几何；完成时使用实际 bounds 校正。新加入 Cell 初始化尺寸后参与协调器动画；动画开始后加入的 Cell 按当前尺寸展示。
- 验证分层：可控协调器在真实 UIKit 环境复现状态覆盖；模拟器 UI 测试使用允许横竖屏的宿主执行系统旋转、手势与画面取证。测试工程可由脚本生成于临时目录，不修改发布工程和生成依赖目录。

## Risks / Trade-offs

- Cell 复用和布局时序复杂 → 用带生命周期观测的测试 Cell 检查第一次布局前准备，以及完成后正常几何更新。
- 自动化状态断言不能证明动画观感 → 另保存系统旋转过程截图并检查，明确设备和 OS。
- SwiftUI CI 的 Xcode 16.4 不支持项目默认 MainActor 隔离设置，导致 Kingfisher 图片加载报错 → 在示例两个图片加载委托回调显式标注 `@MainActor`，以 `@preconcurrency` 桥接库旧委托；不改库公开协议。Xcode 27 默认配置和关闭默认隔离的配置均构建通过，远端旧编译器由 PR CI 验证。
- 原 PR 回推需要 GitHub 写权限 → 本地提交保持可单独移植；只在验证完成且认证可用时回推、运行 CI 和合并。
