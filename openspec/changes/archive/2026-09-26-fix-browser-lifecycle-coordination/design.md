# Design

## Context

问题与范围见 proposal.md。实现依据为 Sources/JXPhotoBrowserViewController.swift、两个 Zoom 动画器、JXPhotoBrowserDelegate.swift、JXPhotoBrowserCellProtocol.swift，以及 UIKit 示例的 VideoPlayerCell 与 DemoViewController。Validation/Rotation 已有可生成的测试宿主。

## Goals / Non-Goals

**Goals:** 保证跨入口的恢复责任唯一、旧交互完成回调不覆盖新交互、数据刷新后不再使用越界索引回调宿主；公开接口保持源码兼容。

**Non-Goals:** 不引入数据模型、通用状态机、第三方加载器或新的尺寸协调协议，不改默认方向和循环算法。

## Decisions

1. 浏览器保存当前隐藏缩略图的视图、原始显隐、索引及可选恢复闭包。增加 `thumbnailRestorationAt` 委托方法（默认 nil），在隐藏前取得闭包，供自定义 alpha/容器显隐捕获原始对象。恢复时优先调用闭包；旧接口仅在索引有效且仍指向同一视图时回调，否则直接恢复已保存视图。刷新时不凭旧索引恢复新数据对象。动画器调用浏览器内部入口；无动画退出通过控制器生命周期恢复。仅给旧索引加范围检查不能恢复已移除的视图，因此不采用该方案。
2. 下拉状态使用小型交互上下文保存 Cell 和进入前的滚动/裁剪/背景状态。异步回弹只结束自身上下文。轮播准入和执行均排除交互、数据同步与页面消失状态；刷新、导航、配置及尺寸转场结束旧下拉。既有 SizeTransition 的身份检查保留。
3. 协议新增 `canBeginDismissInteraction` 默认 true；JXZoomImageCell 实现缩放/到顶判断，并在已有交互回调内保存和恢复自身滚动、裁剪状态。控制器无需知道自定义 Cell 的滚动容器。尺寸转场仍使用现有内置 Cell 接口，避免增加无实际使用者的协议。
4. Demo 增加共享 VideoSaveService：下载回调同步移动临时文件到唯一自有目录，之后交给 Photos；完成或失败都清理自有副本，调用方本地文件不删除。文件接管与清理独立于 Cell 生命周期，UI 回调可以弱引用 Cell。用文件测试与模拟 Photos 消费验证生命周期，补充本地视频的模拟器相册保存冒烟验证。
5. 扩展现有生成工程，增加生命周期和文件测试。CI 单独运行状态测试与稳定的系统交互测试；不把已知受环境限制的 iPad 合成捏合当作通过证据。新增 CI 与本地共用入口，完整保留退出码和结果包。

## Risks / Trade-offs

- 旧自定义显隐依赖按索引查询已替换的数据 → 文档说明动态数据配合恢复闭包捕获原始视图/状态，普通显隐及有效的旧回调保留。
- 宿主恢复闭包强持有浏览器造成循环 → 文档示例弱引用视图，不捕获浏览器。
- 系统手势与模拟器环境影响验证 → 区分可控状态测试、真实系统手势与真机未覆盖项，失败不跳过断言。
- Photos 权限与实际相册写入依赖运行环境 → 文件所有权必须有自动化验证，设备相关限制单独记录。

## Migration Plan

新增协议要求均提供默认实现。README/Guides 说明动态自定义缩略图恢复和 Cell 下拉准入；Demo 使用共享保存工具。全部必要验证完成后同步规格并归档，Git 提交与推送另按用户授权。
